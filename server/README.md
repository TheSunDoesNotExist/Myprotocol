# Myownvpn Server — Debian 12 и 13

Отдельный терминальный установщик сервера протокола v5 для Debian 12 и 13. Без GUI, домена, SNI,
Docker на VPS и замены системного Python. Это TCP-перенаправитель к заданному
`--target`, не TUN-маршрутизация всей ОС. Клиент нужен отдельно, той же версии v5.

## Установка

Готовый серверный пакет этой версии доступен в GitHub Releases:

```bash
release=https://github.com/TheSunDoesNotExist/Myprotocol/releases/download/server-v0.2.3
curl --fail --location --remote-name "$release/myownvpn-server-debian13-v5.tar.gz"
curl --fail --location --remote-name "$release/myownvpn-server-debian13-v5.tar.gz.sha256"
```

Передайте архив на VPS через SCP, сравните его SHA-256 с полученным доверенным
способом значением (или скачайте командами выше) и распакуйте:

```bash
sha256sum -c myownvpn-server-debian13-v5.tar.gz.sha256
tar -xzf myownvpn-server-debian13-v5.tar.gz
cd myownvpn-server-debian13-v5
sudo bash install.sh
```

Если вы вошли как root, выполняйте команды без `sudo`.

С версии 0.2.3 во время установки видны конкретное действие и прошедшее время:
обновление репозиториев, установка системных пакетов, создание venv, загрузка Python
зависимостей, проверка сертификатов и запуск службы. Для apt/pip показывается распознанная
операция с пакетами. Пока команда выполняется, индикатор обновляется; после 15 секунд
тишины появляется время ожидания без новых сообщений. Проценты не выдумываются.
В обычном терминале обновляется строка состояния; при перенаправлении вывода или
TERM=dumb/NO_COLOR печатаются отдельные строки без ANSI. Неизвестные строки команд,
аргументы, пароли и захваченный JSON на экран прогресса не передаются.
Подробный закрытый журнал — `/var/log/myownvpn-install.log`; во втором SSH можно
смотреть его через `tail -f /var/log/myownvpn-install.log`. Выход из просмотра не
останавливает установку. Сам индикатор показывает, что команда ещё не завершилась,
и не гарантирует доступность репозитория или отсутствие сетевого ожидания.

Мастер спросит публичный IP, порт (по умолчанию 443), TCP-назначение, SRTL и
сертификаты. Пример назначения — `127.0.0.1:9000`; на нём уже должно работать
нужное приложение. Перед установкой программы и службы показывается план.
На минимальной системе сначала ставится Python, необходимый самому мастеру.

Предпочтительный вариант — импорт готовых `ca-cert.pem`, `server-cert.pem` и
`server-key.pem`, созданных вне VPS через `ip_cert.py`. CA private key не загружается.
Серверный сертификат должен содержать все указанные IP SAN, без DNS-имён, быть
действующим и соответствовать закрытому ключу. Установщик проверяет это до запуска.

Можно создать identity на VPS: незашифрованный CA key существует только во временном
каталоге `/run`; резервная копия сохраняется как PKCS#8 с паролем от 12 символов.
Пароль не пишется в файлы/логи и не передаётся аргументом процесса. Сохраните
`/etc/myownvpn/backup/ca-key.encrypted.pem` и `ca-cert.pem` вне VPS. CA key не
передаётся службе и не попадает в клиентский пакет. Серверный leaf действует 90 дней.
Автоматическое продление сертификата пока не реализовано: проверяйте срок через status.

Ключ доступа генерируется случайно (256 бит) и скрыт в терминале. Существующий ключ
можно передать файлом с правами 600 через `--key-file`. Не передавайте ключ строкой CLI.
Свежая установка сохраняет его как «Первый клиент» в списке; служебный health-key
генерируется отдельно. Конфигурацию первого клиента можно показать из пункта 5 меню.

## Управление

```bash
sudo myownvpn                  # чистое интерактивное меню
sudo myownvpn status
sudo myownvpn doctor           # реальная локальная TLS/QUIC-проба с проверкой CA/IP/PSK
sudo myownvpn logs             # journalctl, Ctrl+C завершает просмотр
sudo myownvpn srtl on          # без рестарта и потери сессий
sudo myownvpn srtl off
sudo myownvpn clients          # список, состояние и накопленный трафик
sudo myownvpn client-add --name 'Домашний ПК' # создать и показать строку подключения
sudo myownvpn client-show --client ID       # вновь показать конфигурацию
sudo myownvpn client-delete --client ID     # отозвать доступ и закрыть сессии
sudo myownvpn export --client ID --output /root/client.tar.gz # необязательный архив
sudo myownvpn restart          # с подтверждением: прерывает сессии
sudo myownvpn stop
sudo myownvpn start
sudo myownvpn check-update     # только проверить новую версию
sudo myownvpn upgrade          # скачать, проверить и предложить обновление
```

SRTL сервера управляет только его исходящим направлением. Настройка клиента независима.
HUP перечитывает только SRTL; изменение IP/порта/назначения требует рестарта.
Редактирование `/etc/myownvpn/server.json` не должно менять schema/protocol или удалять поля.

В меню пункт 5 открывает список клиентов: имя, ID, статус и накопленный трафик
в обоих направлениях. Здесь можно создать клиента, показать его конфигурацию или
удалить. Строку `myownvpn://…` вставляют в клиент 0.2.0 кнопкой «Вставить конфигурацию».
Она содержит CA certificate и персональный ключ; передавайте её через защищённый канал.
Base64 не скрывает ключ от получателя строки. У каждого устройства должен быть свой
клиент: копии одной строки делят ключ, статистику и отзыв.

Удаление применяется работающим сервером обычно за 0.5 секунды и подтверждается
перед возвратом в меню. Закрываются все сессии клиента, включая ожидающие восстановления;
TCP/UDP и resume со старой конфигурацией запрещены. Остальные клиенты продолжают работу.
Если сервер не подтверждает изменение за 5 секунд, управление останавливает службу
и сообщает об ошибке; удалённый ключ автоматически не возвращается. Если сервер
остановлен, новый реестр будет прочитан до открытия слушателей при следующем запуске.

Счётчики — уникальные байты DATA: ↑ принято от клиента, ↓ подтверждено клиентом.
Повторы при reconnect, TLS/QUIC/HTTP overhead и SRTL не учитываются. Это не учёт
счёта провайдера. Данные сохраняются в SQLite каждые 0.5 секунды и при штатной
остановке; при аварии/отключении питания последняя порция может потеряться.
Статус старше 3 секунд помечается как недоступный. Предел — 256 клиентов.

Необязательный экспорт содержит CA certificate, персональный `access-key`,
`client.json` и CONNECT.txt. Приложение читает архив автоматически. Архив создаётся с правами 600
без перезаписи существующего файла; передавайте через SSH/SCP. Серверного/CA private
key, журналов и исходников клиента в нём нет.

## Что устанавливается

- `/opt/myownvpn/releases/<version>/` — root-owned программа и отдельный venv.
- `/opt/myownvpn/current` — активная версия; venv не перемещается после создания.
- `/etc/myownvpn/server.json` — публичная конфигурация без ключей.
- `/etc/myownvpn/credentials/` — root-only access key и server certificate/private key.
- `/etc/myownvpn/credentials/clients/<ID>` — root-only ключи клиентов для повторного показа.
- `/etc/myownvpn/clients.json` — root:myownvpn 640, разрешённые ID и SHA-256 ключей;
  служба читает реестр, но не может менять его или получать исходные ключи клиентов из файлов.
- `/var/lib/myownvpn/usage.sqlite` — накопленные счётчики и подтверждение применения реестра.
- `/etc/myownvpn/ca-cert.pem` — публичный CA certificate.
- `/var/log/myownvpn/server.jsonl` — JSONL, ротация 5 МиБ × 4 файла; дополнительно journal.
- `/var/log/myownvpn-install.log` — root-only журнал apt/pip/проверок.
- `myownvpn.service` — отдельный пользователь без login shell, systemd LoadCredential,
  read-only system/home restrictions, без root; capability bind-service только для порта <1024.

Штатный Python и venv ставятся из подписанных репозиториев Debian: Python 3.11
на Debian 12 и Python 3.13 на Debian 13. Системный Python не заменяется. Runtime wheels
закреплены версиями и SHA-256, устанавливаются только бинарные файлы с PyPI;
сборки из исходников и неявных зависимостей нет. Поддерживаются amd64 и arm64 при
наличии соответствующих wheels. Интернет нужен для apt и PyPI.

Firewall, SSH, NAT, чужие службы и правила провайдера не изменяются. Разрешите выбранный
входящий TCP-порт и UDP-порт (для auto) самостоятельно в firewall VPS и панели хостера.
Локальная doctor-проба не проверяет доступность порта из интернета. Уже занятый порт
не освобождается автоматически. Никаких внешних сервисов определения IP не вызывается.

## Обновление и удаление

В сервере 0.2.1 и новее: `sudo myownvpn` → **9 «Проверить обновление и обновить»**.
Программа сама обращается к GitHub Releases репозитория `TheSunDoesNotExist/Myprotocol`,
сравнивает номер версии с установленной и скачивает новый серверный пакет. Git на VPS
не нужен. Учитываются только полные опубликованные серверные выпуски с совместимым
протоколом; предварительный выпуск явно отмечается. Обычные коммиты ветки не устанавливаются.
Проверка не выполняет откат на старую версию или повторную установку той же версии.

Перед исполнением проверяются HTTPS, SHA-256 из GitHub API и файла `.sha256`, размер,
безопасность путей архива, версия/protocol в MANIFEST и хеш каждого файла. Загрузка
идёт во временный закрытый каталог. Ошибка загрузки/проверки не затрагивает работающую
установку. После проверки показывается подтверждение перезапуска службы. Можно отменить.
Ключи, клиенты, настройки и SQLite-счётчики сохраняются; соединения при рестарте прервутся.
Неудачная активация вызывает прежний механизм отката. Одновременные установки блокируются.
После успешного обновления откройте `sudo myownvpn` заново, чтобы запустить новое меню.

CLI: `sudo myownvpn check-update` только проверяет; `sudo myownvpn upgrade` устанавливает
после подтверждения; `sudo myownvpn upgrade --yes` подходит для явного запуска без вопроса.
Планировщик фоновых обновлений не создаётся. Нужен доступ к GitHub API и загрузкам GitHub
по HTTPS. GitHub-токен не требуется; при ограничении запросов программа просит повторить позже.

Доверие обновления основано на HTTPS и доступе владельца к репозиторию GitHub.
SHA-256 проверяет целостность, но не заменяет независимую подпись издателя: отдельной
подписи у пакета сейчас нет. Контроль доступа к репозиторию остаётся частью защиты обновлений.

**Первый переход с 0.2.0 и старше:** пункт 9 появится после однократной ручной установки
пакета 0.2.1. Скачайте архив и SHA-256 из выпуска выше, проверьте и распакуйте его.

Из нового распакованного серверного пакета:

```bash
sudo bash install.sh update
```

Новая версия строится отдельно; конфигурация/ключи сохраняются. Активная ссылка
переключается после установки зависимостей. При неудачном запуске/локальной проверке
предыдущая версия и unit восстанавливаются. Рестарт всё равно прерывает удерживаемые
сокеты: откат кода не восстанавливает уже закрытые сессии.

Первое обновление старой установки превращает прежний общий ключ в одного клиента
«Прежний общий ключ». Старые конфигурации продолжают работать, пока этот клиент не
удалён. Создайте персональные конфигурации, затем отзовите общий ключ. Служебный ключ
LoadCredential остаётся только для doctor-проб и сам по себе не открывает DATA-сессию.
Отсутствие/повреждение clients.json закрывает доступ; после миграции пропавший реестр
не восстанавливается автоматически из прежнего ключа. Храните закрытую резервную копию
`/etc/myownvpn`; возврат старой резервной копии реестра может вернуть отозванный доступ.

```bash
sudo myownvpn uninstall
```

Удаляет службу и команду управления с подтверждением. Ключи, конфигурация, журналы,
пользователь и версии программы остаются для восстановления; секреты автоматически
не удаляются. Этот инструмент намеренно не выполняет рекурсивный purge системы.

## Автоматизация и проверка образа

```bash
sudo bash install.sh install --yes --public-ip 198.51.100.10 --port 8443 \
  --target 127.0.0.1:9000 --ca /root/identity/ca-cert.pem \
  --cert /root/identity/server-cert.pem --cert-key /root/identity/server-key.pem --no-srtl
```

Замените примерный IP реальным адресом VPS. Для генерации вместо тройки сертификатов
используются `--generate-identity --ca-password-file /root/ca-password` (права 600).
`--no-start` подготавливает образ и автозапуск без работающего systemd/PID 1.
На обычном VPS этот флаг не нужен. TERM=dumb/NO_COLOR убирают ANSI-цвета.

`python server/admin.py preview` показывает пример терминального экрана без изменений
системы. Сборка отдельного пакета из workspace: `python server/build.py`.
Обновление wheel hashes выполняется разработчиком через `--refresh-lock`; SHA-256
проверяет целостность и не заменяет проверку происхождения самого архива.

## Что проверено

Сервер 0.2.2 добавляет Debian 12. Имя архива/каталога `myownvpn-server-debian13-v5`
сохранено для совместимости с обновлением из меню 0.2.1; пакет поддерживает обе ОС.
Клиенты Windows/Fedora 0.2.0 остаются совместимы.

3 ноября 2026: установка с нуля и обновление в изолированном Debian 13 amd64,
Python 3.13.5; подписи Debian проверены apt, wheels — по SHA-256. Из-за недоступности
прямой сети WSL использовались локальное подписанное зеркало и заранее загруженные
wheels: сетевой источник pip заменялся только в тестовом сценарии.

Проверены права, сохранение ключей при обновлении, откат при неудачной активации,
`systemd-analyze verify`, запуск runtime непривилегированным пользователем,
TLS/QUIC-проба и передача 768 КиБ через TCP → UDP → TCP с одним сокетом назначения.
Переключение SRTL через SIGHUP сохраняет сессию; неверная конфигурация отвергается,
SIGTERM освобождает слушатели, ключ доступа отсутствует в проверенных журналах.
Полный Python-прогон: 73 теста прошли, 5 ECH-тестов пропущены без Go backend.

Работа systemd как PID 1, фактическая выдача LoadCredential, применение sandbox
unit и входящие подключения из интернета в этом chroot не проверялись. arm64
не запускался. На VPS после установки выполните `sudo myownvpn doctor` и подключитесь
клиентом с другой машины. Серверный установщик не включает экспериментальный ECH backend.
