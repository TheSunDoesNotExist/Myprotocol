# Myownvpn — клиент Windows и Fedora 44

Нативное приложение на Qt для существующего протокола v5. Тёмный графит, бирюзовый
акцент, настоящие показатели TCP/UDP и отдельный журнал событий. Программа открывает
локальный TCP-порт и передаёт его на назначение, выбранное сервером. Здесь пока нет
TUN, SOCKS, системной маршрутизации и kill switch; остальные приложения ОС работают
через свои обычные подключения.

## Windows x86_64

Распакуйте `Myownvpn-Windows-x86_64-v0.1.0.zip` целиком и запустите `Myownvpn.exe`.
Python устанавливать не нужно. Приложение запускается от обычного пользователя.
Подпись разработчика пока отсутствует; не изменяйте настройки безопасности Windows.

## Fedora 44 x86_64

```bash
sudo dnf install ./myownvpn-client-0.1.0-1.fc44.x86_64.rpm
```

Откройте Myownvpn через меню приложений. Запускать клиент через sudo не нужно.
Для постоянного хранения ключа используется libsecret и служба Secret Service
вашего сеанса GNOME/KDE. Разблокируйте хранилище ключей при запросе системы.

## Первое подключение

1. На сервере создайте клиентский архив командой `sudo myownvpn export`.
2. Передайте этот **секретный архив** на компьютер через SSH/SCP.
3. В клиенте нажмите «Импортировать пакет» и выберите архив.
4. При необходимости переименуйте профиль двойным щелчком или F2.
5. Оставьте «Автоматически» и нажмите «Подключить».
6. Подключите своё TCP-приложение к показанному локальному порту, по умолчанию
   `127.0.0.1:1080`.

«Канал подключён» появляется только после проверки CA/IP, TLS и ключа доступа.
Неверный сертификат или PSK не разрешают переход к неаутентифицированному пути.
При обрыве существующая сессия восстанавливается в пределах grace сервера.
По завершении сессии нужно подключиться заново: потерянные сервером сокеты вернуть нельзя.
Закрытие окна отключает канал и завершает сетевой поток.

SRTL меняется во время подключения, независимо от настройки сервера. Он добавляет
ограниченное дополнение размеров и короткий хвост зашифрованных сообщений. Это
дополнительный трафик, а не гарантия нераспознаваемости.

## Ключи и журналы

- Windows: `%LOCALAPPDATA%\myownvpn`; ключ — DPAPI для текущего пользователя.
- Fedora: `${XDG_DATA_HOME:-~/.local/share}/myownvpn`; ключ — системное хранилище
  Secret Service. Приложение не сохраняет незашифрованный ключ в конфигурацию.
- Если хранилище недоступно, импортированный ключ используется только до закрытия
  приложения. Интерфейс сообщает об этом; после перезапуска понадобится импорт.
- В `profiles.json` хранятся IP, настройки и отпечаток CA; сам CA — отдельный файл.
- `client.jsonl` содержит метаданные, ротация 5 МиБ × 4 файла. Интерфейс хранит
  последние 2000 событий, поддерживает поиск, уровни и экспорт JSONL.
- Нет отправки телеметрии или журналов третьим лицам. В журнал не передаются PSK,
  приватные ключи, resume-secret и содержимое TCP-потоков. IP и время соединения
  могут быть частью диагностических метаданных; проверяйте экспорт перед передачей.

OS-хранилище не защищает от скомпрометированной ОС или процессов того же пользователя.
Исходный клиентский архив содержит PSK в открытом виде: храните и передавайте его
как секрет, отдельно от опубликованных программных пакетов.

## Запуск из исходников и сборка

```bash
python -m pip install --require-hashes --only-binary=:all: --no-deps -r desktop/requirements.lock
python -m desktop
```

Для явного подключения к первому сохранённому профилю при запуске добавьте
`--connect`. Этот флаг не совмещается с импортом нового пакета.

Для сборки установите `desktop/build-requirements.txt` и выполните:

```bash
python -m pip install --require-hashes --only-binary=:all: -r desktop/build-requirements.txt
```

```bash
python desktop/build.py        # Windows ZIP, либо Linux tar.gz
python desktop/build.py --rpm  # внутри Fedora 44 с установленным rpm-build
```

Результаты — `.local/dist/`, рядом SHA-256. Windows собирается в Windows, Fedora —
в Fedora: PyInstaller не используется как кросс-компилятор. Runtime-зависимости
закреплены версиями и хешами; Qt DLL/.so поставляются отдельно внутри каталога приложения.

Проверки: `python -m unittest test_desktop -v`; полный набор — `python -m unittest discover -v`.
Для изолированного профиля: `python -m desktop --data-dir /path/to/test-profile`.
