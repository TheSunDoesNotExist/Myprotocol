# Myownvpn: восстановление потоков через TCP и UDP

Клиент переключается между **HTTPS CONNECT поверх TCP** и **HTTP/3 CONNECT поверх UDP** на одном
сервере. Приложение сохраняет свой TCP-сокет, сервер сохраняет сокет назначения,
а Session Manager повторяет неподтверждённые события без повторной записи байтов.
Обрыв пути означает паузу передачи, а не немедленное закрытие приложения.

Это TCP port forwarder для одного заданного сервером `--target`. Здесь нет
TUN-интерфейса, SOCKS, маршрутизации всей ОС и переноса исходящих сокетов между VPS.
Текущий формат — v5: клиент и сервер нужно обновлять вместе, v1–v4 несовместимы,
в том числе при выключенном SRTL.
Оба канала шифруются TLS 1.3; собственный ALPN заменён на `http/1.1` и `h3`.
Основной режим — IP без SNI: собственный CA и сертификат с IP SAN, без DNS-имён.
Прямой CLI требует IP endpoints и не разрешает доменное имя как identity.
ECH сохранён как отдельный экспериментальный режим и в основной схеме не используется.
SRTL (Slightly Random Traffic Length) по умолчанию выключен. Включение и пределы:
[TRAFFIC_SHAPING.md](TRAFFIC_SHAPING.md).

## Сервер на Debian 13

Для VPS есть отдельный терминальный установщик: [инструкция](server/README.md).
Готовый архив и SHA-256: [GitHub Release для Debian 13](https://github.com/TheSunDoesNotExist/Myprotocol/releases/tag/debian13-v5-20261103).
Он готовит Python 3.13/venv, IP-сертификат, отдельного пользователя и службу systemd.
Ключи передаются службе через systemd credentials, SRTL переключается без рестарта.
Архив собирается командой `python server/build.py` в `.local/dist/`;
локальные ключи, журналы, тесты и экспериментальный ECH-бинарник в него не включаются.

```bash
tar -xzf myownvpn-server-debian13-v5.tar.gz
cd myownvpn-server-debian13-v5
sudo bash install.sh
```

Перед распаковкой проверьте SHA-256 по инструкции. Firewall и TCP-приложение
назначения настраиваются отдельно. Клиент использует тот же протокол v5.

## Установка и локальный запуск

Проверенная среда — Python 3.14.10. В PowerShell, из папки проекта, при наличии uv
0.13.6 или новее:

```powershell
uv python install 3.14.10 --install-dir .local/python --no-bin --no-registry
uv venv .venv --python .local/python/cpython-3.14.10-windows-x86_64-none/python.exe --seed
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock
python ip_cert.py --ip 127.0.0.1 --out .local/ip-identity
python -c "import secrets; print(secrets.token_hex(32))"
```

В текущем workspace `.venv` уже пересоздана на Python 3.14.10: достаточно активации.
Она использует интерпретатор из `.local/python`; этот каталог нужен для запуска.
TCP использует OpenSSL 3.5.9, криптографическая библиотека QUIC — OpenSSL 4.0.3.
Старое окружение сохранено в `.local/venv-python312-backup`. При установке другим
способом используйте актуальную поддерживаемую сборку Python с обновлённым OpenSSL.

`ip_cert.py` создаёт отдельный CA и серверный сертификат на 90 дней только с IP SAN,
без DNS/CN имени сервера. Ключи не перезаписываются. Для VPS укажите его реальные
адреса через повторяемый `--ip`. `ca-key.pem` храните вне VPS в доверенном месте;
на сервер нужны только `server-cert.pem`/`server-key.pem`, клиенту — `ca-cert.pem`.
CA доверяется только нашему клиенту через `--ca`, системное хранилище не меняется.
`dev_cert.py` оставлен для прежних localhost-тестов.
Напечатанный случайный ключ скопируйте в `MYVPN_KEY` на клиенте и сервере.

В первом терминале создайте папку для тестовых файлов и запустите HTTP-сервер:

```powershell
New-Item -ItemType Directory -Force .local/files
python -m http.server 9000 --bind 127.0.0.1 --directory .local/files
```

Во втором терминале, с активированным окружением:

```powershell
$env:MYVPN_KEY = '<64 hex-символа, созданные выше>'
python tunnel.py server --listen 127.0.0.1:8443 --target 127.0.0.1:9000 --cert .local/ip-identity/server-cert.pem --cert-key .local/ip-identity/server-key.pem --log-file .local/server.jsonl
```

В третьем терминале, с тем же ключом и активированным окружением:

```powershell
$env:MYVPN_KEY = '<тот же ключ>'
python tunnel.py client --server 127.0.0.1:8443 --ca .local/ip-identity/ca-cert.pem --listen 127.0.0.1:1080 --log-file .local/client.jsonl
```

Откройте `http://127.0.0.1:1080/`. Это обычный TCP-порт для HTTP-сервера назначения,
а не SOCKS-порт. Например, файл из `.local/files/large.bin` можно скачать так:

```powershell
curl.exe http://127.0.0.1:1080/large.bin -o .local/download.bin
```

По умолчанию сервер слушает TCP и UDP на одном номере порта. Другие адреса задаются
через `server --udp-listen HOST:PORT` и `client --udp-server HOST:PORT`.
На VPS нужны разрешения firewall для **обоих** протоколов, сертификат для IP VPS
и доверенный ему клиентский `--ca`. Закрытый ключ сертификата остаётся на сервере.
Локальный порт клиента по умолчанию привязан к `127.0.0.1`.

## SRTL — Slightly Random Traffic Length

Добавьте `--srtl` к команде клиента или сервера, чтобы включить объединение DATA,
ограниченный padding и короткий хвост зашифрованных cover-сообщений. `--no-srtl`
явно выключает функцию; отсутствие флага тоже означает выключенный режим.
Каждый конец управляет **своим исходящим направлением**. Можно включить только
клиент, только сервер или оба; получатель понимает SRTL и при выключенной своей отправке.

Профиль: окно объединения 1–4 мс, padding не более 10% уникальных полезных DATA-байтов,
до 4 КиБ cover на хвост и не чаще одного начатого отправкой хвоста за 5 секунд.
Cover расходуется отдельно от 10%-бюджета. ACK/READY/WINDOW не задерживаются.
Пакеты ОС/TLS/QUIC могут отличаться по размерам от дополненных прикладных записей.
SRTL не меняет шифрование и не обещает неотличимость от браузера.

Флаги CLI применяются при запуске. В коде `Session.set_srtl(bool)` и
`Server.set_srtl(bool)` переключают режим действующих сессий без переподключения.
API не открывает удалённый управляющий порт. Уже переданные байты отозвать нельзя.

## Как выбирается транспорт

Клиент каждые 5 секунд проверяет оба пути отдельными защищёнными подключениями.
В низкоуровневом адаптере для TCP используется Happy Eyeballs; для UDP чередуются IPv6/IPv4-адреса DNS
(до восьми адресов). Следующая попытка запускается через 250 мс, не ожидая таймаута
предыдущей. Побеждает первый проверенный QUIC + HTTP/3 CONNECT, остальные попытки
закрываются. В основном CLI endpoints числовые, DNS не используется; сертификат
проверяется по IP из `--server`. Варианты DNS/hostname остаются в тестах и ECH.
После проверки сертификата он отправляет три аутентифицированных запроса с
случайными nonce и измеряет время ответа. Пробы не создают сессии и не вытесняют
действующий транспорт.
Результат каждого пути публикуется сразу: успешный TCP не ждёт таймаута UDP.
Один результат пробы считается одним измерением при проверке hysteresis.

Оценка пути в миллисекундах:

`EWMA(RTT) + 2 × EWMA(разброса RTT) + 300 × EWMA(ошибок проб) + поправка UDP 10 мс`.

Меньшая оценка лучше. При близких значениях предпочтителен TCP. Это оценка
доступности и отзывчивости пути, а не измерение пропускной способности или точного
процента потерь IP-пакетов. Потери и перегрузку внутри QUIC обрабатывает библиотека.

Для планового перехода TCP → UDP другой путь должен выиграть три последовательных
измерения минимум на 10 мс и 20%; после смены действует пауза 10 секунд.
Возврат UDP → TCP требует трёх новых выигранных измерений и той же паузы;
дополнительный порог 10 мс здесь не применяется, иначе он отменял бы предпочтение TCP.
При отказе активного пути эти ограничения не задерживают восстановление.
Измерения старше 15 секунд не используются. Если доступны только старые/неуспешные
пробы, клиент ждёт следующей проверки в пределах срока хранения сессии.

Новый канал сначала проходит TLS/QUIC и аутентификацию, затем HELLO/WELCOME и
READY/READY_OK. До подтверждения READY сервер удерживает прежний канал.
Растущий номер поколения не позволяет запоздалому старому подключению вытеснить
новое. При восстановлении повторяются DATA, OPEN, FIN и RESET, оставшиеся без ACK.

Heartbeat отправляется раз в секунду; отсутствие кадров обнаруживается примерно за
4 секунды. Само подключение и проверка альтернативного пути добавляют время.
Сервер удерживает сокеты 30 секунд после обнаружения обрыва (`--grace 1..300`).
Если приложение само завершило соединение по таймауту, туннель не может его вернуть.

Режимы клиента: `--transport auto` (по умолчанию), `tcp` или `udp`.
В UDP-режиме остаётся QUIC с шифрованием. Сервер можно ограничить `--transport tcp`.
Интервал проб клиента задаётся `--probe-interval 0.5..10`.

## Безопасность

- Оба транспорта требуют аутентифицированного шифрованного канала. TCP использует
  OpenSSL/TLS 1.3, UDP — TLS 1.3 и AEAD в QUIC через `aioquic==1.7.1`.
- Клиент проверяет цепочку сертификата и имя сервера. Общий 256-битный ключ доступа
  проверяется внутри этого канала; для возобновления нужен отдельный 256-битный
  случайный секрет. SessionID не является средством аутентификации.
- Кандидат с ошибкой сертификата или аутентификации исключается до перезапуска
  клиента. Уже проверенный рабочий канал сохраняется; если все кандидаты отклонены
  и действующего канала нет, клиент завершается с ошибкой. Перехода на открытый
  UDP/TCP, опции `--insecure` и отключения проверки нет.
- QUIC 0-RTT и session tickets не используются. TCP согласует ALPN `http/1.1`,
  QUIC — `h3`; далее выполняется настоящий аутентифицированный HTTP CONNECT.
  Собственные криптографические алгоритмы и форматы шифрования не реализованы.
- Экспорт TLS-ключей и QUIC qlog отключён, в том числе через `SSLKEYLOGFILE`. В логах нет payload,
  общего ключа и секрета восстановления; SessionID отображается как короткий хеш.
- Кадры, очереди и число потоков/сессий ограничены. QUIC использует Retry для проверки
  адреса, максимум 64 соединения и один QUIC-stream CONNECT с пределом
  непрочитанных данных 96 КиБ, включая reassembly; credits растут только при чтении.
  Три служебных HTTP/3 stream имеют фиксированный лимит по 4 КиБ; заголовки — 8 КиБ,
  динамический QPACK отключён. Чужие stream отклоняются до выделения буферов.
  Для каждого транспорта отдельно действуют пределы: 64 соединения, до проверки
  ключа — 32 глобально и 8 с одного IP. TCP резервирует слот ещё до выделения TLS,
  QUIC использует Retry. Абсолютный срок авторизации — 5 секунд от принятия TCP
  (включая TLS и HTTP) или создания QUIC; PING его не продлевает.
  Отправка QUIC ограничена 256 КиБ на канал, включая неподтверждённые и ещё не
  отправленные байты. `drain()` ждёт снижения буфера до 128 КиБ; жёсткое превышение
  закрывает канал, не отбрасывая неподтверждённые события сессии.
  Лимиты приложения не заменяют ограничения частоты/SYN на уровне ОС/firewall.

Шифрование туннеля защищает участок **клиент ↔ наш сервер**. Участок сервер ↔ сайт
защищён только если само приложение использует HTTPS, SSH или другое шифрование.
В основном IP-режиме SNI отсутствует; видны IP, время, объёмы и признаки TLS/QUIC.
Низкоуровневый hostname-режим без ECH по-прежнему раскрывает SNI.
Собственного маркера `myownvpn` в ALPN больше нет. Однако TLS/QUIC fingerprint,
рисунок трафика и статическая страница могут отличать сервис от браузера/сайта.
ECH включается через `client --ech-config` / `server --ech-keys` и требует сборки
native backend. В этом режиме виден публичный SNI, внутреннее имя зашифровано;
отказ ECH не допускает прямого fallback. Padding доступен через SRTL;
fingerprint браузера не воспроизводится.
Квоты native backend и схема с дополнительным TLS описаны в [ECH.md](ECH.md).

На серверном порту обычный HTTPS или HTTP/3 GET `/` возвращает статическую страницу
без создания сессии. CONNECT требует ключ в зашифрованном `Proxy-Authorization`
и принимает только фиксированный внутренний адрес `relay.internal:443`.
Это логическое имя сервиса: DNS для него не вызывается, назначение по-прежнему
определяет серверный `--target`. Произвольного CONNECT-прокси нет.

Это экспериментальная реализация, не прошедшая независимый криптографический аудит.
Перезапуск процесса, потеря узла выхода или утечка ключей не покрываются механизмом
восстановления. Общий ключ рассчитан на одного владельца, а не на много пользователей.
Подробности и проверка зависимостей: [SECURITY.md](SECURITY.md).

## Логи и анализ

Консоль и `--log-file` используют JSONL: одна JSON-запись на строку, время UTC,
`role`, `pid`, уникальный `run`, хеш `session`, `path`, идентификатор `transport`.
Файл ротируется при 5 МиБ, сохраняются три предыдущих файла. DEBUG включается через
`--log-level DEBUG` и добавляет sequence, StreamID и offsets, без содержимого кадров.

| Событие | Что показывает |
|---|---|
| `secure_connection`, `connect_success` | TLS-версия, cipher, HTTP carrier, длительность подключения |
| `address_attempt`, `address_connected` | Номер UDP-попытки, семья IPv4/IPv6 и время подключения |
| `address_failed`, `address_cancelled` | Отказ проверки безопасности, таймаут, сетевая ошибка или отмена попытки |
| `path_probe` | RTT, jitter, доля ошибок проб, оценка пути, число попыток |
| `path_selected` | Выбранный путь, предыдущий путь и причина выбора |
| `transport_lost`, `transport_attached` | Причина отказа, поколение, время без транспорта |
| `frame_replayed`, `duplicate_discarded` | Повтор неподтверждённого события и дедупликация |
| `session_metrics` | Принятые/доставленные байты, буферы, inflight, заблокированные credit потоки |
| `stream_credit` | Абсолютный credit потока, DEBUG без полезной нагрузки |
| `candidate_quarantined`, `connection_rejected` | Изоляция кандидата или отказ аутентификации |
| `authentication_timeout`, `connect_superseded` | Истечение срока авторизации или устаревшая попытка |
| `connection_limited` | Отказ TCP до TLS при исчерпании общего/неавторизованного бюджета |
| `send_buffer_limited` | Заполнение жёсткого бюджета отправки QUIC, байты и лимит |
| `ech_backend_started`, `ech_accepted` | Режим обязательного ECH и проверенный внешний канал |
| `ech_connection_failed`, `ech_backend_failed` | Отказ ECH/сертификата/ключа или остановка backend |
| `srtl_configured` | Включение/выключение локального исходящего SRTL |
| `stream_failed`, `session_closed` | Ошибка сокета или причина закрытия сессии |

Например, просмотр переключений:

```powershell
Get-Content .local/client.jsonl | ForEach-Object { $_ | ConvertFrom-Json } | Where-Object { $_.event -in 'path_selected','transport_lost','transport_attached','candidate_quarantined' } | Format-Table time,event,path,reason,generation
```

`downtime_ms` считает период без привязанного канала, не полный простой приложения.
Метаданные журналов тоже могут быть чувствительными: храните их с правами владельца.

## Тесты и оставшиеся ограничения

```powershell
python -m unittest -v
```

Тесты используют настоящие TLS/TCP и QUIC/UDP. Проверяются сохранение одного сокета
при TCP → UDP → TCP, молчащий UDP blackhole, потеря ACK после доставки перед сменой
транспорта, потери и искажения UDP-пакетов, HTTP-загрузка 3 МиБ с SHA-256,
несколько потоков, half-close, дедупликация OPEN/FIN, истечение сессии, неверные
сертификаты/ключи и запрет перехвата сессии старым поколением.
Отсутствие видимого plaintext в захвате UDP — дополнительная проверка, а не аудит AEAD.

Проверки A01–A08 из аудита включены в обычный
прогон через `test_hardening.py`. Аварийное закрытие application-сокета использует
abortive close с TCP RST; обычный FIN/half-close остаётся штатным завершением.
Это проверено на Windows; соответствующая ветка Linux требует отдельного прогона.
Для A08 проверяется отсутствие собственного ALPN и явно фиксируется остаточная
видимость SNI. Дополнительные тесты проверяют обычный HTTP/3-клиент, авторизацию
CONNECT, лимиты заголовков, IPv6 → IPv4 и отмену адресных попыток.
Текущий статус A08 и исторические результаты: [AUDIT.md](AUDIT.md).

Управление ресурсами отдельно проверяется в `test_resources.py`: лимиты TCP до TLS,
общий deadline TLS + HTTP, освобождение сессии без READY, завершение обработчиков,
QUIC backpressure/STOP_SENDING и завершение подключения назначения после RESET.
Переключения сериализованы; активный путь и reader публикуются до ожидания очистки
старого канала. Повторное переключение на уже рабочий путь не создаёт дубликат,
а автоматический выбор, рассчитанный до другого handover, отбрасывается.
Штатное переподключение сохраняет подтверждённую сессию в течение grace;
незавершённая новая сессия освобождается сразу. Остановка сервера отменяет и ждёт
принадлежащие ему задачи; таймеры QUIC останавливаются до закрытия UDP-сокета.
Закрытые application-потоки отпускают reader/writer, сохраняя состояние дедупликации.

В текущем окружении прошли 69 Python-тестов, включая SRTL-бюджеты, раздельное включение,
живые переключения, потерю ACK и padding без повторной записи, IP-only TCP/UDP ClientHello,
отказ при неправильном IP сертификата, полный CLI с ECH/UDP,
сохранение сокета при ECH TCP → UDP → TCP и анализ расшифрованного QUIC Initial.
Отдельно запускаются пять Go-тестов `go -C native test -v ./...` с подслучаями
отказа ECH/сертификата/ключа и захватом TCP ClientHello. При отсутствии собранного
backend Python ECH-тесты явно пропускаются; остальные проверки остаются доступными.

В передаче допускается 16 неподтверждённых событий; каждый поток имеет независимый
credit 64 КиБ и отдельную задачу записи. ACK подтверждает приём в Session Manager,
а не запись в сокет назначения. Медленный сокет ограничивает свой поток; контрольные
WINDOW передаются отдельно от надёжной очереди и повторяются при восстановлении.
Шифрованный carrier пока общий: транспортный head-of-line при потере пакетов остаётся.
Дальнейшие улучшения — отдельные QUIC-streams и адаптация окон к RTT/бюджету памяти.
Максимум 16 сессий на сервер и 128 потоков за время одной сессии, включая завершённые
состояния дедупликации. После достижения лимита завершите потоки и перезапустите клиент.
Исходящие очереди ограничены 64 кадрами плюс 16 в передаче, входящая — 16 кадрами.
Каждый поток хранит до 64 КиБ полезных байтов приёма; дополнительно существуют
буферы ОС и криптографической библиотеки. Перезапуск процесса теряет эти буферы.

Остановка процесса сервера не имитирует отказ транспорта: она уничтожает удерживаемые
сокеты. Перенос на другой VPS требует постоянного узла выхода и отдельного relay-слоя.
Формат и гарантии: [PROTOCOL.md](PROTOCOL.md).
